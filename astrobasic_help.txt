[intro]
What is AstroBasic? (Dutch translation by Willem Simmers below)

AstroBasic (AB) is a computer language specially designed for astrology. It's a domain specific language made for astrology.

An AB program is a textfile with AB code. 

The language works in two steps, first a textfile (the sourcefile) with extension AB is analyzed (parsed) and checked for errors as much as possible. A binary version of your code is made (a file with extension ABC) and saved to disk when the parse completes successfully. 
If it doesn't, e.g. an error is found, you are put in the editor at the line where the error occurred. 

When running, the binary version is used for speed.

All statements in a AB program are terminated with a semicolon (;).

Variables must be declared before they can be used. Declaration of variables can be anywhere in the program, but it is best to keep them together for readability. 
All variables in a file are global to that file, e.g. you can use them anywhere, but in functions you can declare local variables. Variable names have a length of at most 30 characters.

Underscores and digits are allowed. A digit cannot start a variablename or labelname. 

The language is case sensitive, all intern commands and variables are lower case. Something like GOTO doesn't jump! Use exact case. The variables Aa, aa, AA and aA are four different variables!

All arrays start from 0, this means if you need an array of 10 items you declare it as int a[10]. But if you want the first element you  have to refer to a[0] and if you want the 10th element you refer to element 9. Once you get used to this approach you wouldn't want to miss it.

Whitespace is mostly ignored, you can write something like a*1+b, but you can't write something like gotomain. 

When editing or creating an abprogram, see ^Text Editor^, context sensitive online help is available. To access help on a command or internal variable, place the cursor in the editor on the command and press F11, or right click the mouse and choose Context Help from the popup menu, or choose Help-Context from the editor menu.

Also, a fully integrated debugger is supplied, to trace program flow, inspect variables, program output etc. See ^Debugger^.

Intro
Wat is AstroBasic?

AstroBasic (AB) is een computertaal die speciaal is ontworpen voor astrologie.

Een AB-programma is een tekstbestand met AB-code.

De taal werkt in twee stappen, eerst wordt een tekstbestand (het bronbestand) met extensie AB geanalyseerd (ontleedt) en zoveel mogelijk gecontroleerd op fouten. Er is een binaire versie van uw code gemaakt (een bestand met extensie ABC) en op schijf opgeslagen wanneer de analyse met succes is voltooid.
Als dit niet het geval is, bijvoorbeeld als er een fout is gevonden, wordt je automatisch naar de editor geleidt, bij de regel waar de fout is opgetreden.

Tijdens het uitvoeren wordt de binaire versie gebruikt voor snelheid.

Alle instructies in een AB-programma worden afgesloten met een puntkomma (;).

Variabelen moeten worden opgegeven voordat ze kunnen worden gebruikt. Variabelenverklaringen kunnen overal in het programma voorkomen, maar het is het beste om ze bij elkaar te houden voor de leesbaarheid.
Alle variabelen in een bestand zijn globaal voor dat bestand. Je kunt ze bijvoorbeeld overal gebruiken, maar in functies kun je lokale variabelen opgeven. Variabele namen hebben een lengte van maximaal 30 tekens.

Underscores en cijfers zijn toegestaan. Een cijfer kan geen variable naam of labelnaam starten.

De taal is hoofdlettergevoelig, alle interne commando's en variabelen zijn kleine letters. Zoiets als GOTO springt niet! Gebruik exact geval. De variabelen Aa, aa, AA en aA zijn vier verschillende variabelen!

Alle arrays (groepen van variabelen) beginnen bij 0, dit betekent dat als u een array van 10 items nodig heeft, u deze als int a [10] opgeeft. Maar als je het eerste element wilt, moet je naar een [0] verwijzen en als je het 10e element wilt, refereer je naar element 9. Als je eenmaal gewend bent aan deze benadering, zou je het niet meer willen missen.

Whitespace (witregels) worden meestal genegeerd, je kunt iets schrijven als een * 1 + b, maar je kunt niet zoiets als gotomain schrijven.

Bij het bewerken of maken van een abprogram. ^Astrobasic Editor^ is er contextgevoelige online-hulp beschikbaar. Voor hulp bij een opdracht of interne variabele, plaatst je de cursor in de editor bij de opdracht en klik je op F11. Of je klikt met de rechtermuisknop en kiest Context Help in het pop-upmenu, of je kiest Help-context in het editormenu.

Ook wordt een volledig geintegreerde debugger geleverd, om de voortgang van het programma te traceren, variabelen- programma-uitvoer te inspecteren, enz. Zie ^Astrobasic Debugger^.
[notations]
Notations used in this manual
When describing the syntax of functions the following notations are used:

If a function returns a number wich could be important, it is preceded with the type of that number.

Examples:

midi(10, 100);  $ returns nothing of interest, so there is no preceding type $
char ask(char caption[$], char question[$]); $ returns 0 or 1 so only a char type is returned $
real sqrt(real number); $ returns a floating point number $

If an argument to a function is a single dimension (i.e. not an array) the function simply states the type to which that number is converted to before the function is executed.

Example
window(int width, int height);
You can call the function with any number, even a floating point, but it willl be converted to type int when executing the function.

If an argument to a function is an array of any kind, this array must be declared. If dimensions to this array are documented, the declared array must be of EXACTLY the same dimension.

Example:

getplanets(char horoscope, real planets[16]); 
$ an array of exactly 16 reals must exist $

If a function is documented with a array type of any dimension it is documented with empty brackets.

Example:

strset(char Destination[], etc.

Here 'Destination' can be a char array of any size.

If a function is documented with a char array wich holds a $ between the brackets, this means that 1. the array can have any dimension and 2. the array can be a stringconstant.

Example:

addlistbox(char text[$]);

You can:;

addlistbox("This is a string");

but you can also:

char text[90] = "bla bla";
addlistbox(text);

And also:

addlistbox(planetname[2]);

If a function needs to store an value but not into an array, the type of the value is followed by a *. This means that such a variable must exist because the function wants to store a value.

Example:

char getrealnumber(char Caption[$], char Message[$], real *Result);

The argument to *Result must be an existing real variable, because the result from the function will be stored there.

If a funcion expects a label (the name of a subroutine) as one of it's arguments, it is documented with the word 'label'.
Example: 

button(int X, int Y, char Caption[$], label OnClick);

If a function can handle any kind of variable, regardless of type or array dimensions, it is documented without any type or array notation.
Example: 

move(source, destination);

Pointers:
If a function wants a pointer as a parameter it is indicated with a &
Example: memwrite(char blockno, int index, &var);

[variables]
Variables
Variables are in four types, so called 'datatypes'. 
There are:
· char
(space in bytes: 1,    min. value: -128,    max. value: 127
· short
(space in bytes: 2,    min. value: --32768,    max. value: 32767)
· int
(space in bytes: 4,    min. value: -2147483648,    max. value: 2147483647)
· real
(space in bytes: 8,    min. value: -1.7E-308,    max. value: 1.7E-308)

For each of the above datatypes arrays are possible, up to two dimensions.

About the variable types:
The name 'char' is an abbreviation of 'character', it has the smallest size but can hold a value from the ASCII character set. An array of char is therefore used to keep sequences of characters or strings. So it is handy for characters as well as variables of small size.

The next two, short and int, are used to hold integer values (as opposed to floating point values) of bigger size than a char. 

Their names are related to the native size of processor registers. Currently this is 32 bit, i.e. 4 bytes, so the 'most normal' size for the processor to hold an integer value is a variable with a size of 4 bytes, i.e. an int. Since it not always nessecary to need 4 bytes to store a value there is a 'shorter' version of an int wich is only two bytes in size, hence 'short'.

(In the days of 16 bit machines, 'int' was two bytes and a variable with a size of 4 bytes was called a 'long').

While the names from above datatypes come from the c language, the name of the floating point type 'real' comes from the pascal language. It is called 'real' because it is able to present a value like 0,5, wich can't be presented by the other types.

For reasons of simplicity, the datatype 'short' is not used for any of parameters for the functions. If a value can fit (-128 to 127) into a char type (or character strings are used), the type will be a char. If a value of floating point is required, the type will be real and all other parameters will have type int, (although they might fit into the range for short). This way, it will be easier to remember wich type of argument a function has.

Examples of declaring and initializing variables:

int a; $ declares a variable 'a' of type int $

The size of an array must be positive, a negative size gives 'Size mismatch'.

Note that the declaration ends with a ; like all AB statements.

char a[40]; $ declares a one-dimensional array 'a' of 40 chars $

real x, y[10][10]; 

$ declares a floating point variable 'x' and a  twodimensional array 'y' of floating points with dimensions 10 x 10 $

Variables can be initialized when declared. Examples:

int a = 1;

int b[3] =     {1, 2, 3}; $ there must be exact 3 initializers $

int c[3][3] =  {1, 2, 3},    {4, 5, 6},   {7, 8, 9}; $ there must be exact 3 x 3 initializers $

char a[12] =   "Hello world"; $ a must be big enough for 11 chars + 1 $

char a[3][3] = "Hi",   "o",  "Ho";   
$ There must be 3 stringconstants but a  stringconstant can have less characters then 3 $

char a = 32;

or..

char a = 'x';

A single char can be initialized with a 'character constant', which must be enclosed in single quotes and should be a single character.

Variables can be initialized with other variables or with expressions or functions. E.g. char a = b; char a = 1 + 1, int records = openread(databasename).

Note that when using 'real' datatypes values can get rounded. Take care with comparison between two 'real' types and using the equalityoperator = For instance 1/3 will be represented with something like 0.33333333 which is not _exactly_ the same. Most of the time, this will not matter, however.

IMPORTANT
A variable of a given type can only hold values in the range suitable for that type.
If you add 1 to a char variable that currently holds the value 127, it will 'wrap around' and will contain the value -128.

Also, if  a function expects a variable of type int, and you feed it a variable of type real, the value gets truncated.

These effects can be used for tricks, see: Tips and Tricks.

[operators]
Operators
These are the operators you use in an expression like a = b * 3;

*multiply
/divide
%modulus
+addition
-subtraction

Multiply, divide and modulus all have the same precedence, the highest precedence. Addition and substraction both have the lowest precedence. Precedence can be altered with ().
Dividing by 0 gives the error 'Divide by 0', also with modulus: a value % 0 is an error.
A minus followed by a space is allowed: a = - 5; a = 3 * - 2;

Examples:

a = 2 * 3 + 4;		` 'a' will be 10 
a = 2 * (3 + 4);		` 'a' will be 14 
a = 4 % 3 * 2;		` 'a' will be 2 
a = 4 % (3 * 2);	` 'a' will be 4 

See also: Assignment

[conditions]
Index BackConditions
Conditional operators are

< smaller than
> bigger than 
= equal to
<= equal to or smaller than 
>= equal to or bigger than 
!= not equal to
in check to see if one value is part of a set of values
notin the reverse of above 

Conditions can be combined with boolean operators, these are:

or
and

You can also use

||
&&

Boolean operators have no precedence and the complete condition is evaluated from left to right.

Precedence can (only) be given using ( ).

Evaluation stops as soon as the result is known: in if (i < n and a[i] = 5) a[i] is not evaluated when i >= n, and in if (a = 1 or @f(x) = 1) the function is not called when a = 1. Exception: a 'for' loop with an 'in' condition always evaluates everything.

A function called in a condition may contain conditions itself (if, while, for).

String constants and character constants containing ( or ) are allowed in a condition, f.i. if (c = '(').

A boolean operator must have whitespace immediately before and after it, otherwise it can get confused with a variable name like color, which contains the letters 'or'. This is especially unclear in combination with symbols, like in if (a =  or  = a), where there will be an error 'unknown command' on 'or ' because 'or' is not recognized. (For those of you who are familiar with the dbase language, there you must use for instance .and. In lotus you must use #and#)

The 'in' conditions checks to see if a value is part of an array. For example:

int a[3] = { 0, 3, 6};
if (b in a) { statements; }

above executes only if b has one of the values in a[].

See also: ^if^

[assignment]
Assignment
AB is default assignment. This means that whenever a command is not recognized, an assignment is assumed. So you don't have to write something like 'LET a = 1'.
An assignment consists of an 'leftvalue', an assignment-operator and a 'rightvalue'.

A leftvalue means a variable of some kind, i.e a place to store some result.
A rightvalue can be any allowed expression.

These are the assignment operators with examples:

operatorexamplecomment
a = 1;		assign to a the value 1
a += 1;		increment a with the value 1
a -= b;		decrement a with the value of b
a *= 10;	mulitply a by 10.
a /= 5;		divide a by 5.
a %= 3;	assign a % 3 to a.

ATTENTION! Always consider the type of your variable when you do assignment. A variable of type char can only hold integer values from  -128 to 127. If you add 1 to a charvariable which holds now 127, it will wrap around and become -128. 

Same for divisions, if you divide by two and don't assign this value to a 'real' datatype, the value will be truncated! This can be very usefull however, because to get the sign from a longitude, you can just divide by 30 and assing the result to a int variable or to a function that expects an int.
 
a /= 0 and a %= 0 give the error 'Divide by 0'.

Every array index is checked, also a negative one: a[-1] = 1; gives 'Array out of bound'.

See also: Variables.

Labels

Syntax: :labelname;

A label in this context identifies a subroutine. You write the code of the subroutine after the labelname and at the end of that code you write the return; statement. A label must start at the beginning of a line.

You call a subroutine by:
@labelname;

Some functions also use a label as one of their arguments.

Note: there is also a function label for textoutput on a window, which should not be confused with this topic.

About functions:

- A function must start at the beginning of a line.
- A function can have local variables.
- You don't have to supply a return.
- String constants are only allowed as single array argument, i.e. function("hello") is allowed.
- Error checking: for array parameters there is error check on type and size of the parameters, for single values typecasting is done:
- You can access global variables declared anywhere before the function body.
- The header and body can be on one line: #f() { return 1; }
- 'return value' outside a function gives the error 'Return value outside function'.
- A function cannot call itself (no recursion), local variables are not saved.
- The number of parameters is limited, too many give the error 'Too many arguments'.

Syntax

Or

In the first case everything between $ and $ is ignored.

Frequently asked questions
Q: My program only runs correctly the first time.

A: You probably forgot to reset a loop counter. If you have something like this:

:SomeSubRoutine;
for (i < 10)
   {
   etc.
   }
return;

And you call that subroutine the second time without modifying 'i', it will be10 because that is it's value after executing the loop the first time.
All variables get initialized to 0 when a program begins, that is why you didn't see this the first time.

Q: My variable does not seem to get initialized:

A: It's probably outside reachable code, i.e if you have:

$ initialisations $

run:

:Subroutine;
...
return

int myvariable = 5;

the initialisation to 5 is code to execute, but this code is placed between labels, so it won't get executed.

[errors]
errors

; expected

 You forgot to put an ; at the end of a statement. This error also occurs if AB can't make sense of some source code, it's a general error.

$ expected

You have began a 'rem' statement somewhere and forget to end it.

 ] expected

You tried to use or declare an array and forgot the closing ]. Tip:   In PD's editor you can use the matchpair functions to trace these kind of errors quickly.


 [ expected

You are using an array but forgot to index it properly.

( expected

You forgot an (.
Usually this is when you use a function which expects it's arguments in the () or after an if, else, while for statement which expects conditions in the ().

) expected

Somehow you forgot an ).
Tip: In PD's editor you can use the matchpair functions to trace these kind of errors quickly.

{ expected

You forgot an {.
Probably when initializing an array.

} expected

You forgot an }.
Usually as the end of an 'if', 'else', 'while' or for loop or in the declaration of an array. Tip: In PD's editor you can use the matchpair functions to trace these kind of errors quickly.

" expected

You started a stringconstant but forgot the closing ".

, expected

When initializing an array, you forgot an element, or messed it up otherwise.

Unbalanced "
Unbalanced $

These two errors occur when a $ has no closing $ or when a " has no closing "

{ or " expected.

Also when initializing an array, there is no opening { or " for the initialization.

- Label not found:

You tried to call or goto a label which doesn't exist.

- Assignment operator expected

When a command is not recognized an assignment is expected in the form: LeftValue AssignmentOperator Rightvalue. This error occurs if a

LeftValue is found but not an assignmentoperator.

- Conditional operator expected

A condition in an 'if', 'while' or 'for' block can't be parsed correctly because an conditional operator was expected.

- Variable not found:

You used a variable you have not declared, see the section on declaration of variables.

- Duplicate variable name:

You have tried to declare a variable which has already been declared with that name in your source file.

- File not found

A file was not found. Maybe it is somewhere else. Did you make a backup?

- Size mismatch

These errors occur for instance in the 'move', 'sort' and 'getdisk' functions. For 'move' 'len' must fit in both source and destination, counted from the given element.

- Type mismatch

When initializing arrays or giving arguments to functions a type check is made. F.i. the first argument of juliantotime must be an array of type int and dimension 6. Check the syntax of the function you are trying to use.

- Too many labels

The maximumnumber of labels is 1000.

- Too many variables

The maximumnumber of variables is 1200.

- Too many blocks

The maximumnumber of blocks is 2000.

- Too many calls

[button]
button

Syntax: button(int X, int Y, char Caption[$], label OnClick);

Action: Creates a button at position X, Y with caption Caption. If the button gets pushed, the label OnClick is called.
The function returns the number of the button created, this is 0 for the first button, 1 for the next and so on.

If you preceed any of the characters in Caption with a &, that character gets underlined and will be a keyboard shortcut to use for that button.

   say("Hey!", "You pushed me!");
   return;

window(200, 200);

[command]

Action: 'command' is a repository for a lot of functions. At the moment most perform an action on some control. There are predefined constants for parm1, these are:

BUTTON, LABEL, CHECKBOX, EDIT, MENU, UPDOWN, WINDOW, BITMAP, PROGRESS, GRID, EDITOR, DRAW, RADIO, LIST, MEMO, SELECT, COMBO, CHECKLIST, TEXT, GROUP

If 'parm1' is either BUTTON, LABEL, CHECKBOX, EDIT, MENU, UPDOWN, PROGRESS, COMBO and parm2 equals -1 the last created control is deleted ('parm3' and 'parm4' are ignored).

[db]
db

Syntax: db(int cmd, int a, int b, char s[$]);

Action: This is a small database function, where cmd is
0: creates or opens a database with name 's' and record size 'a'.
1: reads the record with number 'a' into the structure at 'b'
2: writes into record number 'a' the structure at 'b'
3: deletes the record with number 'a' 
4: deletes the entire db
5: closes the db so you can use another
6: assumes the db structure starts with a string and finds the record that has a string that's equal to 's'
7: returns the number of records

Example: this script has functions to test this, use write to write the 12 signs into the database, read to read them, del to delete them etc.

menu(0, "Read", read);

memo(0, 0, width, height, 0, 0);

  db(3, 0, &name, "");
  return;

:del;

  return;

[define]

Action: Replaces any further occurances of the string NAME with the value 'Value', much the same as the C preprocessor command. After this NAME can be used in expressions and will be translated to the value.

[escape]
escape

Syntax: escape(labelname);

Action: Checks whether there is an event waiting for the label in 'labelname'. 
If so, leaves the current event, resets the callstack to the way it was before the event was called, and then calls the label in 'labelname'. 
If there is no event waiting, the function does nothing.

Remarks:

This one is a bit difficult to understand.

When a button gets pushed, astrobasic calls the subroutine associated with that label and executes this code until the return statement. This is called an event. 
There can only be one event executing at a time so if you push a button while that first event is still executing, astrobasic does nothing.
This means you cannot have for instance a Cancel button, because pushing it would have no effect while something in an event subroutine is still executing.

The function escape however provides such a mechanism.

Example:

button(10, 10, "&Execute", Execute);
button(10, 40, "&Cancel", Cancel);
run;

Cancel;
 return;

:Execute:    
 ` very long routine to generate 1000000 horoscopes etc.
 for (i <1000)
 {
 ... do all kinds of things
 escape(Cancel);
 ... do all kinds of things
 }

Now when the code in Execute reaches escape(), it looks if the Cancel button was pushed (actually, it looks if there is an event waiting for the Cancel label). 
If so, it leaves Execute and calls the code in Cancel, which does nothing but return to run (because Execute would have normally also returned to run), i.e. the code in Execute is effectively cancelled.

(tech note: allowing more than one event at a time to be executed would be 'interesting', because when a button gets pushed in the middle of some code executing, the other code would get executed until it returns to the exact point where the button was pushed in the first event which can be in the middle of some calculation. Mostly this is not exactly what would be desirable.)

[findaspect]
findaspect

Syntax: int findaspect(real start, real end, char p1[16], char asp[11], char option[20], real angle, real lon, real lat, real zone);

Action: Finds all kinds of planet events like aspects in/out/exact, retro/direct, cunjunctions with housecups. The search starts at julian date 'start' and ends at 'end' . A search will be made for aspects in the array 'asp' for planets in the array 'p1'. The results will be put into block number 'no'.

0 do retro, set this to 2 to include post/pre events.
1 do inout
2 sign
3 blockno
4 orb
5 sid
6 dec
7 doob
8 zeromax
9 exit after first find ingress
10 void of course.
11 negate retro longitudes

A program that uses this function must first reserve memoryblock 0 like this:

^memget^(0, n, 36);

where 'n' is the maximum number of entries you want, eacht entry takes 19 bytes.

real findjd; ` the julian date at which the event was found

01 retro
2 conj cusp
3 out of orb
4 in orb
5 exact
6 sign ingress
7 post retro
8 pre retro
9 decl in orb
10 decl exact
11 decl out orb
12 oob
13 inb
14 decl 0
15 decl max
16 void of course

  {
  memval(0, i, &findjd);
  juliantotime(findjd, time);
  timetostring(time, ds, ts, 0);
  strset(s, "%s %s %i", ds, ts, findp2);

  }

[for]
for

This command has, like all commands that work with a block, two kinds of syntax:

Syntax: for (condition) statement;

Or:

Syntax: for (condition) { statements; }

Action: The commandblock is executed as long as 'condition' evaluates to true, otherwise a jump is made to the end of the block. 
Each time the end of the block is reached, the first variable in 'condition' is incremented by 1.
The first variable in the first condition of a for loop must be a plain int variableclass=rvts3.

Example (this will put the names of the first 12 planets on the screen):

int p1 = 0;
for (p1 
 putstring(10, 10 + p1 * 20, planetname[p1]);

(Note: when this loop is finished, p1 will have the value 12)

Another use of for, is with an 'in' condition. For example:

int a, b[3] = { 1, 4, 8}, c = 0;
for (a in b)
 {
 putnumber(10, c, a);
 c += 20;
 }

will print: 
1
4
8

When the loop first starts, the variable 'a' is set to the first value in the array 'b', then to the second value etc. until all values in 'b' are processed. There can be only ONE 'in' condition in a for loop.

Note: The very first variable in the condition must be an int, for (0 < n) gives 'for-variable must be int'.
Note: There can be more conditions then one, for example:
for (i  5)
but only the first condition is treated as a for condition, i.e. 'i' will be incremented automatically since it is the first variable in the condition, but 'b' will not.

See also: ^conditions^, ^while^, ^if^

[if]
if

This command has, like all commands that work with a block, two kinds of syntax:

Syntax: if (condition) statement;

Action: If 'condition' evaluates to true the statement is executed, otherwise a jump is made to the next statement.
Or:
Syntax: if (condition) { statement; }

Action: If 'condition' evaluates to true the statement or block of statements is executed, otherwise a jump is made to the end of the block.
An alternative use is:
somevariable = if (somecondition);

Here, somevariable will be 0 if the condition turns out false and 1 if the condition turns out true. No jumps are made.

Notes:

- If there is only one command you don't need to use {} like:

if (i = 0)
 quit;

If there is more than one command that should be executed when condition is true, you should use {} like:

if (i = 0)
 {
 midi;
 quit;
 }

- There cannot be two consecutive commands like this without a block, so:

if (i = 0)
 if (a = 0)

is illegal and will give the error "{ expected".

(The above could also be written as 'if (i = 0 and a = 0)' 

There are other situations like:

for (i < 9)
 if (i = 0)
    midi;

This will also give an error. You must supply {} for the 'if' part, like:

for (i < 9)
 {
 if (i = 0)
 midi;
 }

See also: ^conditions^, ^else^, ^while^.

[include]
include

Syntax: include "somelibrary.ab";

Action: The code (functions or labels to call and optionally global variables) in 'somelibrary.ab' gets included in the current file.

Libraries cannot be nested.
The maximum number of libraries is 10.
A library must have windows CRLF line endings, like the main file.
A program can use more than one library.
if a label exists with the same name as the library (but without extension) the label will be called automatically when the file is included..

Simple example, this program displays 6:

include "somefunction.ab";
real a = @fun(3);
char s[99];
strnum(s, a, 5);
say("", s);

------------------------
file somefunction.ab:

#fun(real x)
{
return x * 2;
}

[memcpy]
memcpy

Syntax: memcpy(int sourceblock, int sourceoffset, int destblock, int destoffset, int length);

Action: copies 'length' bytes from memoryblock 'sourceblock' at offset 'sourceoffset' to memoryblock 'destblock' at offset 'destoffset'.
If sourceblock or destblock is less then 0, the astrobasic variable heap is the 'memoryblock' so you can use pointers to vars to read from or write to.
This function treats memoryblocks as untyped, so you can copy any kind of data, regardless of the typesize of the memoryblock but you must remember to use bytes for indexing.

Warning! No kind of error checking whatsoever!

Example memory juggling:
memget(0, 10, INT);  ` get memory for 10 ints in block 0
memget(1, 10, INT);  ` get memory for 10 ints in block 1
int a = 9, c = 2;          
memwrite(0, 1, &a);       ` write the contents of 'a' which is 9, into block 0 at index 1
memcpy(0, 4, 1, 0, 4);   ` copy the contents of block 0, 4th byte, to block 1, 0th byte, with len 4 bytes, this copies the int from block 0 index 1 to block 1 index 0 so it now also contains '9'
int b = memread(1, 0);  ` read contents of block 1, index 0 into b (value 9)
memcpy(0, 4, -1, &c, 4); ` copy that value into variable 'c'

See also: ^memget^, ^memread^, ^memval^, ^memwrite^, ^memsort^


[memget]
memget

Syntax: char memget(int blockno, int size, int type);

Action: Allocates 'size' items of 'type' bytes in memoryblock 'blockno'. 
If 'size' is 0, the block is freed.
if the allocation is succesful, returns 1, else returns 0;
The block is filled with value 0.

You can use the constants CHAR, SHORT, INT and REAL for 'type', but you can also define a type of your own.

There are 256 memoryblock available, so 'blockno' must be between 0 and 255.

Use these functions with care! The only check is made on a valid blocknumber, so you could easily corrupt memory and probably get a crash from windows.

The debugger has a menuentry 'Dump' which makes a dump of the block to a file. Select the number of the memoryblock and you will get a file called 'Dumpxx.txt' (where xx is the number of the block). If 'type' is either CHAR, SHORT, INT or REAL, the debugger will put these values in the file, else it dumps the bytes which make up that structure.
The debugger will then try to execute that .txt file so it will be available in your texteditor.

See also: ^memread^, ^memwrite^, ^memval^, ^memset^, ^memcpy^, ^memget^, ^memsearch^

[memsearch]
memsearch

Syntax: memsearch(int blockno, int stringoffset, char searchstring[$]);
Action: searches blockno at stringoffset for searchstring, returns number in block or -1 if not found.

Example:

int i, n = readopen("jean.db", 0);
real planet[PLANETS];

` this is the structure for memget/read/write, 69 bytes total
real sun;
char name[61];

for (i < n)
  {
  readrecord(0, i);             
  getplanets(0, planet);
  sun = planet[0];
  getname(0, name);
  memwrite(0, i, &sun);
  }
i = memsearch(0, 8, "Jean Cremers"); ` search for this name
if (i < 0)
  say("", "Not found");
else
  say("", "found");
run;

Any character in the formatstring is copied into the destination, except for sequences beginning with the character %. These are formatspecifiers for arguments following the formatstring. 

This function is closely related to the c standard library printf function.
The syntax of the format string is:

% [flags] [width] [.prec] type_char

where typechar can be (a % without a valid typechar gives the error 'typechar not recognized'):

s for strings
d for integer numbers
f for floating point numbers
a for angles.
c for a single character.
t for a tab character.
p for a planetsymbol in text or putsymbolstring.
i for a signsymbol in text.
e for an aspectsymbol in text.
n a newline.
l this looks up the supplied argument in the current Language file for translation.

width:

n At least n characters are printed. If the output value has less than n characters, the output is padded with blanks (right-padded if - flag given, left-padded otherwise).
0n At least n characters are printed. If the output value has less than n characters, it is filled on the left with zeros.

.prec:

.0 for f types, no decimal point is printed.
.n n characters or n decimal places are printed. If the output value has more than n characters, the output might be truncated or rounded. (Whether this happens depends on the type character.)


flags:
-	Left-justifies the result, pads on the right with blanks. If not given, it right justifies the result, pads on the left with zeros or blanks.
+	Signed conversion results always begin with a plus (+) or minus (-) sign.
blankIf value is nonnegative, the output begins with a blank instead of a plus; negative values still begin with a minus.
width:
n	At least n characters are printed. If the output value has less than n characters, the output is padded with blanks (right-padded if - flag given, left-padded otherwise).
0n At least n characters are printed. If the output value has less than n characters, it is filled on the left with zeros.
.prec:
.n n characters or n decimal places are printed.

If the output value has more than n characters, the output might be truncated.

Angles:
0: No seconds are displayed and the value will a modulus of 30 degrees
Example: value = 123.5, output will be 3.30°
1: Seconds are displayed and the value will be a modulus of 30 degrees
Example: value = 123.5, output will be 3.30°00"
2: No seconds are displayed and the value will not be taken modulus.
Example: value = 123.5, output will be 123.30°
3 Seconds are displayed and the value will not be taken modulus.
Example: value = 123.5, output will be 123.30°00"
4: this formats a declination.
5: this formats a declination with seconds.

Examples:

char buf[100];
real r = planet[SUN];
int s = r / 30;
strset(buf, "The planet %10s is in sign %12s at degree %0a", planetname[SUN], signname[s], r);

The output will be something like:
"The planet sun is in sign aries at degree    3.30°"

If you want to display the '%' itself, use %%. Example:

strset(buf, "The value is %d%%.", value);

Note: use %d for integer numbers, %i prints a signsymbol.
The width can be at most 200 and the precision at most 100, else the error 'format width too large' is given.
If the result does not fit in 'Destination' it is cut off, a %s string that does not fit is left out.
The maximum number of parameters is 48.

See also: ^strcpy^, ^strcat^, ^strnum^

[Debugger]
This is the astrobasic debugger.

The debugger is an integral part of astrobasic, that means Ab was designed to have a debugger right from the start, it is not something that was added later on. This is because a debugger is such a handy tool, it is not only there to find bugs, it is also a means of checking out if the code you wrote actually does what you expect it to do.

The debugger can be invoked from the editor when editing an astrobasic program. Click on a line of executable code and press F8

You see a window with the sourcecode in the upper half of the window highlighted on the first line with executable code.

In the lower part of the window there is space to inspect variables. In programming jargon, these are called watches, and that's what they are called in this help section too.

First note that if you move the mouse over the barrier between the two windows, you see the cursor change because you can drag that border to give more or less space to the watch window.

Now for the general use of the debugger.

First, it is important to always have an eye on the caption of the debugger, this tells the state the debugger is in. Initially this is 'debugger active'.

Let's start with the upper window where the source code is displayed.
As said, the first line with executable code is highlighted. Now besides the menu commands you can:

1. Double click on a line. The debugger will run the astrobasic program to the point JUST BEFORE it reaches that line. So that line is not executed yet. If you double click on the next line, that previous line gets executed and so on.
You can also use the Step command to advance to the next command.
Note however that sometimes it takes more than one click on Step to execute a line because a line can consist of more than one command. For instance if you have something like 'a = max(b);' the max function gets executed as well as the assignment to 'a', so two clicks on Step are needed.

IMPORTANT NOTE, a line you doubleclick must contain executable code otherwise the debugger will not react on that line and simply run the program.

2. Single click on a line (or use any of the cursor keys). The caption of the debugger changes to 'press Cursor to trace to this line'. This means the debugger has noticed you are browsing around in the sourcefile and waits for you to find a right spot. Once you found that spot (the line you are interested in) you can click on the menucommand Cursor (or doubleclick on that line, which is the same). 

If the program has not yet reached that line, the debugger caption says 'Debugger waiting for line to execute'. This is for instance if you told it to go into a label associated with an event from a button. The astrobasic program will run untill that button is pushed and once your line is reached, the debugger window gets focus again and 'Debugger active' is displayed.

A program will not react to events (buttonclicks etc.) UNTIL AFTER the run statement has been executed. This means that if you are debugging a program and have not yet reached and executed the run command, a push on a button or a click on a checkbox will not do anything, it will be ignored by the debugger.

Once the run command has been executed, the caption of the debugger changes into "Run function. Debugger waiting for event." and focus will shift from the debugger to the running program. If you now push a button or click a checkbox with an associated subroutine, the debugger will get focus again at the start of that subroutine.

A quirck in the debugger is when you on a line with an if like this

if (condition)
command;

Now when you Step, the debugger will always advance to the line with 'command;' BUT it will only execute it if condition = true. Write the conditon like this:

if (condition)
{
command;
}

If you want to follow the execution flow in the debugger.


Watches.

The watch command from the menu pops up a box in which you can enter the name of any variable you are interested in. You can enter names of arrays too.
A special case is if you hover the mouse over a variable, the first entry in the watchbox will always display the value of that variable. Use this as a quick look at variables.
Hold Control over a variable and it will be added to the watches.

These watches are remembered between debug sessions, into a file called 'watches.dat', delete the file if you want to start with no watches.
If you right click on the watchbox there's a popupmenu to edit or delete that watch, also if you press Enter on a watch, you can edit it.

If you want one special element from an array, you can provide a simple digit as index, i.e. int a[3][2];
You can have a watch on a, it will display the entire array, or you can have a watch on a[1], or you can watch a[b].

In the latter case, consider the following situation:
int a[10];
....
for (i < 10)
{
a[i] += 1;
...
}

When above loop is finished in a normal way, 'i' will be 10. So the debugger has a problem because a[10] does not exist because a has indexvalues from 0 up till 9.
In stead of the debugger reporting something like 'out of bounds', it just shows the last value, in this case the one from a[9]. 

There is room for maximal 20 watches, just double click on an empty place in the watchwindow to enter a watch at that place.

The other commands are:
Edit, quits the debugger and puts you in the editor at the place where you were while debugging.
Dump, makes a memorydump, see astrobasic help for memget.
Run, quits the debugger and runs the program.
Calc, starts the little calculator
Quit, quits the debugger and returns to PlanetDance

See also: ^Text Editor^

Any program that uses a window will also have a contextmenu to be invoked by a right mouse click. This menu contains:

Copy to clipboard
Save Bitmap
Print

These commands all act on any drawing or textoutput done on the window, but not on buttons or labels. They act only on the bitmap, so you won't see any buttons if you print a window, just the graphical output.

----------------------------------------
There are two special kind of windows possible, the first is when you use window(0, 0);

This makes the script window an 'MDI child', Multiple Document Interface, it embeds itself in the main program just like a horoscope (or graph or moving wheel). The Horoscope menu changes to a menu with the name of the script and it will contain all the menu() items from the script.

You can do command(MENU, 0, 12, 0); preferably on the line just before run; it will do two things:
- it will make a copy of the menu in the script mainmenu into a rightmouseclick popmenu, so the user can rightclick anywhere in the window for the script menu (just like the horoscope window).
- it will add a menu item Output, with subitems Copy to clipboard, Save Bitmap and Print to both menus.

You can also put a special ^button^ on the script like this
button(x, y, "Menu", NULL);
command(BUTTON, buttonnumber, 10, 0);

^setcaption^ will only set the upper caption in the mainwindow, if you want it to change the caption in the tab use command(FUNCTION, 67, x, 0); where x is on/off.

You should use 'width' and 'height' when designing your window and try to fit at least on 1920x1080 as well as 1366x768, in this case you can support the majority of screensizes.

----------------------------------------
The other special window is with width < 0 . 
The script will not have it's own window but instead outputs stuff on the current horoscopewindow and then quits. An example is gauqueling.ab, when invoked, it draws those cusps in the horoscope.

You can put the horoscope(s) from the window in the horoscope array of such a program with copyhoroscope so you can use things like getplanets(0, planets);
Use -2 to ensure that the horoscopewindow is not a synastry, and the wheel is drawn, not the aspectpage. This also does a clear
The global var screentype gets set after the window has been made and holds the type of screen:
0 no synastry, only wheel fits
1 no synastry, only 1 column, no elem
2 no synastry, enough room for column and elements
3 no synastry, enough room for column and elements and the aspecttable
4 synastry, only 1 wheel fits
5 synastry, only 1 column, no elem
6 synastry, 2 columns, no elem
7 synastry, enough room for 2 columns and elements
8 synastry, enough room for 2 columns and elements and aspecttable
Not all functions can be used in this kind of program, generally, for instance interactive functions that otherwise could be on a plain astrobasic window like menu or button etc.

Lastly, you can make a window scrollable so it can contain more info by using command(WINDOW, 3, width, height);

See also: ^run^, ^button^, ^menu^, ^command^, ^copyhoroscope^

[searchaspect]
searchaspect

Syntax: searchaspect(real start, real end, int p1, int p2, int as);

Action: Searches for aspect as between p1 and p2, from start to end, returns julian day if found, else returns 6000000.

Example:

int time[6];
real jd = getsystemtime(time);
jd = searchaspect(jd, jd + 30, SUN, MOON, CONJUNCTION); ` search for the next new moon
real zone = gettimezone(defaultplace, jd);
juliantotime(jd + zone, time); ` make local time
run;

See also: ^findaspectx^ ^findpos^ ^searchaspect^  ^searchaspectx^

[searchaspectx]
searchaspectx

Syntax: searchaspectx(real start, real end, int p1, int p2, int h, int as);

Action: Searches for aspect as between transit p1 and p2 from horoscope h, from start to end, returns julian day if found, else returns 6000000.

Example:

int time[6];
real jd;
jd = getsystemtime(time);
copyhoroscope(-1, 0);
jd = searchaspectx(jd, jd + 370, SUN, MOON, 0, CONJUNCTION); ` find the moment when transit sun is conjunct moon in horoscope number 0.
real zone = gettimezone(defaultplace, jd);
juliantotime(jd + zone, time);
run;

See also: ^findaspectx^ ^findpos^ ^searchaspect^  ^searchaspectx^
[setlonlat]
Syntax: setlonlat(char Index, real *Lon, real *Lat)

Action: sets the longitude and latitude of the place from horoscope 'Index'.

Please note: PlanetDance follows the convention of the Swiss Ephemeris calculation routines. Western longitudes are negative, Eastern are positive. 

See also: ^gethoroscopeplace^, ^strlonlat^, ^getlonlat^
[syzygy]
Syntax: syzygy(real jd, real lon, real lat, char mode);

Action: gets the syzygy for birthtime jd and lon, lat. If mode = 0 the moon longitude is returned, if 1, the julian date is returned.
